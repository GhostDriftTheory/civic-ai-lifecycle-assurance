# 自治体AI・派生情報ライフサイクル・アシュアランス｜PoC第3弾

> **開発中・正式発表前（暫定公開）**：本リポジトリは合成データによる技術PoCです。HTML等に記載されたクラウドシエンとの協業・共同PoC・社名表示は協議を前提とした暫定表現であり、正式な共同事業、実証開始、対外発表を示しません。実施内容・公表表現は関係者による最終確認を経て確定します。

**AIが作った情報にも、使える条件と、利用終了を認められる範囲を残す。**

元情報 → 模擬AIの要約 → 起源別の条件承継 → 後続利用の制御 → コピー・未終結操作の確認 → 範囲付きの利用終了記録 → 独立した履歴再計算、を一続きに実行します。

本版は**第1段階：オフライン・模擬AI版**です。実APIは接続せず、APIキー・追加Pythonパッケージ・サーバー起動は不要です。実住民情報、非公開の庁内規程、顧客データ、特許明細書を同梱していません。第1・第2弾のファイルも変更しません。

**重要な境界：このPoCでいう利用終了は「指定した管理ゲート経由の業務利用の終了」です。媒体上の物理消去、管理外コピーの不存在、監査記録からの情報消失、OpenAI等の提供者内部の削除を意味しません。**

## まず見る・動かす

`civic_lifecycle_poc_demo.html` をブラウザで開き、**「条件の承継」→「部分変更」→「残るコピー」**の順に操作してください。「次の処理を実行」で状態を引き継ぎ、各段階の理由・条件・経路・記録を確認できます。Pythonとは独立してブラウザ内で動きます。

Pythonで実ファイルまで生成するには、リポジトリのフォルダで次を実行します。

```console
python poc.py
```

表示された `output/run-識別子/report.html` をブラウザで開きます。WindowsでPython Launcherを使う場合は `py poc.py`、環境により `python3 poc.py` でも実行できます。コードはPython 3.10以降の文法を使用します。

## 何が実用性として見えるか

架空の相談情報Aには「相談案内のみ」「期限」「監査義務」、架空の業務資料Bには「内部利用のみ」「監査義務」があります。要約Sには両方の条件を起源別に保持します。入力の寄与が不明でも、宣言した入力の条件を勝手に除外しません。模擬AIが「条件なし」と返す試験でも、その自己申告で制限を解除しません。

対象Sの目的条件について有効な模擬変更証拠がある場合だけ、承認済み二次利用を追加します。**Sの二次利用が可能になっても、B由来の内部利用制限・期限・監査義務は残り、元のAの条件も変わりません。** 変更証拠は、出力ID、派生イベント、内容、変更前の条件と版、権限、有効期間、一回の使用に結び付けます。

利用終了では、新規利用を停止するだけでは証明を作りません。要約・コピーの読取り経路が残る場合は不採用、実行結果・範囲・閉鎖証拠が未確認なら保留とし、必要な確認が揃った場合だけ、起源・範囲・業務状態版・世代・有効期間・保持例外を伴う記録を生成します。

### 13の連続シナリオ

| シナリオ | 実演する違い |
|---|---|
| 条件承継 | 要約後の内部相談利用はPASS。未承認の二次利用・外部提供はREJECT |
| 部分変更 | 目的条件だけを変更。内部二次利用はPASSでも外部提供と元情報の二次利用はREJECT |
| 証拠不足 | 変更をHOLDにし、元条件を保持。許される通常利用は継続可能 |
| 証拠の結合 | Sの証拠を別のコピーCへ流用するとREJECT |
| コピー残存 | A・Sを閉鎖してもCが残れば終了しない。Cも閉鎖して初めて終了成立 |
| 結果不明 | 予約・不明操作を保持。遅れて判明したDも登録・閉鎖してから終了 |
| 一覧欠落 | 対象実体・能力・登録一覧を照合。未登録を利用不能とは扱わない |
| 旧証明 | 経路を復元した後は、過去の証明を現在の根拠として適用しない |
| 管理外 | ローカルの業務利用終了と、管理外コピーまで含む終了を分離 |
| 監査保持 | 監査用データを保持したまま、例外なしの終了・完全消去を主張しない |
| AIの制限解除申告 | 模擬AIの「条件なし」を採用せず、制御側で条件を承継 |
| 不明経路 | 観測不明を閉鎖とみなさずHOLD。必要な前提の閉鎖後は再評価 |
| 期限切れ承認 | 対象が同じでも、有効期限を過ぎた変更証拠はREJECT |

`inventory_drop`、`route_restore`、`route_unknown`、`remote_copy` は異常状態を作る**試験専用操作**です。特に `remote_copy` は管理外に情報が存在する状況を合成するもので、利用ゲートが外部転送を許可したことも、実送信したことも表しません。画面・実行結果でも区別しています。

## 実装と実際の作用

PythonとJavaScriptは、同じ入力から独立して状態を計算します。判定結果を事前に表示しているだけではありません。

派生処理が許可された場合だけ、出力本体、親、起源、条件、利用経路を管理ストアへ登録します。通常の `use` で情報本体を取得できるのは利用判定がPASSの場合だけです。`close` は管理ストアの読取り経路を無効化し、その処理前後の実際の状態を閉鎖記録にします。単なる「閉鎖済み」という任意入力は受け付けません。復元された経路は世代を更新し、以前の閉鎖記録を新しい経路の閉鎖に流用しません。

予約済みコピーは、入力・起源・条件・出力先を先に記録します。結果不明は非実行とみなさず保持します。完了結果から遅れてコピーが判明した場合は、新しい終了阻害要因として評価します。模擬実行器が非実行を確定した場合だけ取消しとして終結させ、確定済み結果の再送で作用を増やしません。

完全性は、起源に関連する**管理対象の実体と固定の読取り能力**から必要経路を求め、実際の経路表・登録一覧と照合します。経路表と一覧の両方から項目が消えても、対象実体が残る限り欠落として検出します。ただし、そもそもこの管理ストアに捕捉されない未知の情報・OS上のコピーを発見する機能ではありません。

### 出力先

```text
output/
  run-識別子/
    report.html
    summary.json
    self_tests.json
    シナリオ名/
      audit/
        evidence.json
      business/
        S-secondary-internal.txt   # 最終状態でも許可される場合のみ
```

`audit/evidence.json` は合成入力、過去の出力、承認・閉鎖記録を含む、**保持例外として明示する監査用の証拠**です。`business/` には、実際に供給された文案のうち最終状態でも同じ用途で利用できるものだけを保存します。終了した起源の過去の文案を、有効な業務出力として残しません。

これらはPoC自身の管理ストア・生成ファイルの制御です。利用者が監査JSONを直接開いたり、コードを改変したり、ファイルを別にコピーすることをOSレベルで阻止する実装ではありません。ローカルの合成デモから実サービスへ移すには、認証・永続化・アクセス分離・経路の強制仲介が必要です。

## 再検証

```console
# 保存された監査記録と、現在有効として書き出した業務ファイルを検査
python poc.py verify output

# 単独のJSONは履歴を再計算（同梱のない業務ファイルは検査しない）
python poc.py verify "lifecycle-pending-audit.json"

# 一つのシナリオだけ実行
python poc.py run --case pending

# 自己テスト
python poc.py test
```

再検証は固定の初期状態からコマンド列を再実行し、各判定、条件、状態版、前後状態、閉鎖記録、証明内容、最終状態を照合します。提出された「検証済み」フラグや結論を、そのまま信用する方式ではありません。判定を改変して連鎖と全ハッシュを再計算しても、再実行と整合しない記録は拒否します。

一方、ハッシュは電子署名ではありません。第三者が別の整合的な履歴全体を作ったことを、このデモだけで真正な実履歴と識別することはできません。承認者・操作結果も合成フィクスチャであり、実在する主体の認証ではありません。

**過去の記録の再現成立と、現在の利用終了証明の適用は別です。** `apply_certificate` は状態ハッシュ、業務状態版、起源世代、期限、終了条件を改めて照合します。模擬時計は業務状態版と分けて管理し、期限内の時間経過だけで証明を失効させず、期限終端は除外します。実運用の巻戻し検出には、当該保存データの外側の信頼された現在状態が必要です。

ブラウザの「証拠と範囲」ではPython生成JSONも再検証できます。ブラウザの保存JSONをPythonで検証することもできます。読み込みは検証結果の表示だけを行い、操作中の管理状態を勝手に置き換えません。

## Leanの形式検証と実装照合

`CivicLifecycleAssurance.lean` は、8条件の利用判定、変更証拠の6条件、起源別条件の承継と部分変更、4値の前提評価、6条件の利用終了判定、証明の現在適用を定義します。70の名前付き定理の証明コードを含みます。

中心となる性質は、証拠なしでは条件を緩和しないこと、変更対象外の条件と起源を保持すること、不明・競合を不存在としないこと、残存可能経路・予約中・結果不明の操作がある間は終了を認めないこと、保持情報には例外の明示を要すること、状態や世代の変わった証明を現在に流用しないことです。

```console
# Leanモデル本体
lake build

# Python/JavaScript照合、Leanモデル・具体命題・証明依存の全検査
python poc.py ci

# Leanを使わない検査。結果には lean_checked: false と表示
python poc.py ci --runtime-only
```

CIは181の処理列、817操作についてPython・JavaScriptの**全結果・全状態・記録ハッシュ**を照合します。さらに、処理前の管理状態から観測入力を作り、Leanモデルによる条件・判定・供給・証明発行・条件更新と、Pythonの実結果を照合する具体命題を検査します。8入力の判定集約6,561通りと、単一経路の前提16通りも検査対象です。生成ファイルは小さなバッチに分け、巨大な一括証明を避けています。

モデル定理と生成した名前付き照合定理の双方で依存公理を確認します。未証明の穴や独自公理、コンパイラの計算結果だけを信頼する証明への置換は認めません。許容する標準依存は `propext`、`Quot.sound`、`Classical.choice` だけです。

**形式証明の対象はLeanモデルです。** 目的・提供先・期限の原子的な照合、証拠や状態の同一性、登録の捕捉、認証、JSON正規化、SHA-256、I/Oは観測境界に置きます。全Pythonプログラムとモデルの全入力に対する意味的同値性を証明したものではありません。有限の実装照合も、実AIの精度や全欠陥の不存在を意味しません。

## 第1・第2弾との関係

第1弾は回答を採用できる条件と証拠、第2弾は入力・送信・出力採用のプライバシー条件、第3弾は生成後の条件承継・継続利用・利用終了を扱います。今回はそれぞれ独立して再現できる技術PoCです。第1・第2弾のJSONスキーマへの自動変換や、3つの実行時の一体化は実装していません。

## 次段階の実API接続

本Pythonの `GeneratorPort` / `MockGenerator` に、要求ID、入力内容の識別値、模擬生成の結果、応答識別値を受け渡す境界を用意しています。AIが返す本文と、制御側が付ける起源・条件を分離しています。実APIのコード、SDK依存、APIキーの読込み、課金を伴う呼出しは本版にはありません。

次段階では、送信前の許可確認と実行意図の永続化、実APIアダプター、応答との結合、タイムアウト時の結果不明保持、提供者側の保持範囲の記録を追加します。**関数を外部API呼出しへ置き換えるだけで、実送信や外部での利用終了まで保証できるとは扱いません。** 現行の資料Bは内部利用限定なので、そのまま実APIへ送る変更は不可です。実API用の合成入力・送信先・処理条件を別途確認します。

`store: false` の指定やローカルの削除だけで、提供者内部の全データ消去を証明したことにはなりません。実接続時には対象エンドポイントとアカウントに適用される保持条件を公式資料で再確認し、未確認の外部範囲をローカルの終了成立へ混ぜない設計にします。

## 編集時の注意

`cases.json` の `reference` はPython・JavaScript・Leanの同じSHA-256に固定しています。変更は単なる表示の編集と区別し、3実装と証明モデルをレビューしてください。シナリオを編集した場合は、HTML内 `demo-data` との同期と期待判定も確認します。配布版は同期済みです。

JSONはASCIIキー・安全整数・文字列・真偽値等の限定した領域を使います。重複キー、不正な型、未知のコマンド、出力識別子の重複等は拒否します。汎用JSON正規化規格の完全実装ではありません。模擬時刻は実時計でなく整数のカウンタです。

実行時は毎回別フォルダを作り、過去の結果を上書きしません。通常のHOLD・REJECTは検査対象の業務判断であり、期待どおりなら正常終了です。処理エラーや検査不一致は非ゼロ終了になります。
